# Development seed and Enrollment API

## Run

Production/default startup runs Flyway only and never invokes the sample-data component.

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=dev"
```

The `dev` profile activates `DevelopmentDataSeeder`. Its initial dataset is a single transaction, uses natural-key markers to avoid rerunning, and stores BCrypt hashes generated by the configured `PasswordEncoder`.

## Enrollment API

| Method | Route | Permission |
|---|---|---|
| GET | `/api/v1/enrollments` | `enrollment:read` |
| GET | `/api/v1/enrollments/{id}` | `enrollment:read` |
| POST | `/api/v1/enrollments` | `enrollment:create` |
| PUT | `/api/v1/enrollments/{id}` | `enrollment:update` |
| PATCH | `/api/v1/enrollments/{id}/cancel` | `enrollment:cancel` |
| POST | `/api/v1/enrollments/{id}/transfer` | `enrollment:transfer` |
| POST | `/api/v1/enrollments/{id}/freeze` | `enrollment:freeze` |
| PATCH | `/api/v1/enrollments/{id}/complete` | `enrollment:complete` |

List filters: `page`, `size`, `sort`, `search`, `status`, `classId`, `studentId`, `campusId`, `source`, `enrolledFrom`, and `enrolledTo`. Detail responses conditionally include parent contacts only with `enrollment:read-parent-info` or `parent:read`.

## Verification

1. Start PostgreSQL and run the application with the `dev` profile.
2. Log in through `POST /api/v1/auth/login` using an account above.
3. Call `GET /api/v1/enrollments?page=0&size=20` with its bearer token.
4. Run `.\mvnw.cmd test` for migration validation and the full test suite.
